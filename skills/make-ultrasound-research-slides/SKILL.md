# 超声电路科研 PPT

## 默认设置

- 优先制作面向同行科研人员的外出交流报告，保留组会、论文精读、开题、答辩与会议报告模式。按用户当次明确指定的场景调整。
- 接受自然语言描述和少量图片，不要求用户先填写完整表单或自行写出逐页大纲。
- 默认使用中文，保留常用英文缩写，并在首次出现时按需要解释。
- 默认采用 16:9、白底、深蓝主色与少量青色点缀的学术风格。遵循用户提供的模板、参考页面和语言要求。
- 未指定报告时长时，按 20 分钟规划约 14–18 页主体内容。说明这是规划假设，再根据技术复杂度调整。用户指定的总页数包含封面及附录，除非另有说明。
- 默认交付可编辑的 PPTX。用户指定其他目标格式或演示文稿平台时遵循其要求。用户只要大纲、单页或局部修改时按请求范围交付。
- 默认主动检索补足缺少的背景、相关研究、机制解释和有依据的性能比较。

## 1. 接收材料并确定汇报主线

1. 阅读用户的文字、图片和附件；使用可用的图像查看能力检查原理图、波形、测试照片及论文截图。
2. 提取主题、报告场景、听众、时长或页数、主要研究问题、实际完成的工作、核心贡献和已有证据。复用当前对话中已经明确的信息。
3. 识别超声应用及项目范围。按材料判断发射、接收、收发接口、控制、阵列或其他模块，区分芯片设计与板级实现。不要默认所有超声项目都是医学成像，也不要默认必然包含整条收发链。
4. 仅在缺失信息会影响研究事实或主要结构时追问，优先把相关问题合并为一个简短聊天问题。对于配色、常规排版和页数分配使用上述默认值。不要重复询问已经提供的信息。
5. 如果尚不知道具体报告主题或用户自己的主要工作，先询问这两项；等待回答时可以整理已有材料和检索背景。不要替用户虚构一个研究项目。
6. 在内部建立内容清单，分别记录用户提供的事实、核实的文献事实、计算或分析、研究假设及待补材料；为每个数字和主要结论记录出处、条件与证据状态。
7. 用一两句话说明计划采用的主线和关键假设，然后继续完成制作。除非用户要求先确认大纲，或关键研究事实仍不明确，不设置强制的大纲批准步骤。

## 2. 主动检索并补充内容

1. 根据实际缺口设计检索问题，例如应用需求、现有电路架构、特定机制、相关指标或已有方案的局限。按需组合中英文关键词，不用一组泛泛的超声搜索替代针对性研究。
2. 使用可用的联网检索能力，优先查阅原始研究论文、出版社或会议官方网站、作者公开的原文及官方器件数据手册。对于当前研究水平和最新成果核对发表日期及正式版本。
3. 阅读与要引用的结论直接相关的原文、图表或可核实摘要；核对论文题目、作者、年份、出处以及实际存在的 DOI 或 URL。只对实际能够核实的内容作出陈述，不用检索摘要拼出完整电路机制。
4. 优先选择少量直接相关的可靠来源，通常先从 3–6 个来源开始。按内容需要调整，避免为了充实页面堆砌无关论文。
5. 用检索内容补充问题背景、相关工作、设计权衡、公开的电路机制及可比数据。明确标识“文献结果”“本工作”“设计目标”“仿真结果”或“实测结果”。
6. 只把用户确实完成或明确提供的工作作为其研究成果。引用其他人的数据不能补成用户的测试结果，也不能据此宣称用户方案已经验证。
7. 缺少验证数据时，先完成能以现有材料支持的页面，把实际缺口整理为简短的补充材料提示。按场景使用明确标注的目标、验证计划或待验证机制；不要绘制虚构曲线、填写猜测的性能数值或制造“首次”“最优”的结论。
8. 对影响结论的来源分歧或不可比条件作出说明。无法联网或无法访问原文时明确报告限制，用现有材料继续完成可支持的内容，不声称检索已经完成。
9. 在相关页用简洁可读的文献编号或短引文标识外部事实；在备注或参考文献页记录作者、题目、年份、出处及 DOI/URL。使用可独立理解的引用，不把工具内部引用 ID 当作文献。为外部图片记录图号或页码及来源。

## 3. 按汇报场景选择结构

| 场景 | 主线与内容重点 | 需要保留的区别 |
|---|---|---|
| 外出同行交流，默认 | 应用或研究问题、现有方法的局限、自己的设计思路、关键机制、验证证据、贡献和待讨论问题 | 保留足够技术细节让同行评估方案，把低价值的基础科普和冗长推导放到备注或备用内容 |
| 学术会议报告 | 聚焦一个清晰问题，用核心创新与最有说服力的证据支撑结论 | 按报告时长控制信息量，保留必要对比与局限，扩展推导作为备用内容 |
| 组会进展 | 阶段目标、已完成工作、设计改动、仿真或测试结果、异常分析、需要讨论的问题、下一步 | 清楚呈现失败尝试、未完成工作和需要组内判断的事项 |
| 论文精读 | 问题与动机、核心架构和电路、关键原理、验证方法、性能对比、局限、对自身研究的启发 | 区分作者结论、用户自己的判断和建议，不把论文贡献写成用户贡献 |
| 开题 | 研究背景、相关工作、尚待解决的问题、研究目标、技术路线、可行性依据、验证方案、时间安排 | 使用拟开展或计划的表述，区分已有基础与预期结果 |
| 答辩 | 研究问题、方法、已完成成果、验证与对比、明确贡献、局限和后续工作 | 让每项贡献对应实际证据，区分团队已有工作与本人承担的部分 |

按实际材料选择和合并段落，不强制每份报告出现所有模块。为每页确定一个具体目的、一条核心信息及其证据。用框图、关键电路局部、时序、曲线、照片或精简表格承载解释；把长段落的推导和讲解写入备注。通过机制、条件、设计取舍和证据增加内容厚度，而不是重复文字或增加空泛页面。

## 4. 检查超声芯片与板级电路的技术表达

- 按材料检查系统、芯片模块、板级器件和测试平台之间的边界。把商用器件搭建的板级原理验证与自主设计芯片的结果分别说明。
- 对电路图和框图保持已知的连接、端口方向、元件值、供电域和模块层级。仅在连接信息足够明确时重画可编辑图；不清楚的部分保留原图、询问或标注为概念示意。
- 对发射相关材料按需呈现输出幅度、负载、波形或脉冲条件、时序、工作频率和功耗条件；对接收相关材料按需呈现带宽、增益、噪声、动态范围、线性度、恢复或串扰等实际相关指标。不要自动给每个项目增加全部指标。
- 对板级材料按需呈现接口、供电、器件分工、测量连接和验证范围。保留照片或原理图中能够确认的事实，不从外观推断板层数、工艺、通道数或具体器件型号。
- 区分原理级仿真、含寄生仿真、芯片电学实测、板级实测与声学或系统实验；根据材料标明证据阶段。电学验证本身不能支持尚未完成的声学或系统性能结论。
- 核对量纲、频率或带宽条件、负载、增益与电源条件。区分峰值与平均功耗、每通道与整机功耗、噪声谱密度与带宽积分噪声，保留原文定义。
- 整理文献对比表时统一指标名称与单位，标明仿真或实测及关键测试条件。对于不同条件的结果保留差异说明；缺失数据填“未报告”或明确的缺失符号，不推算未知性能。
- 对用户给出的曲线优先使用原始数据。仅有截图时忠实保留坐标、单位、图例与测试条件；估读须标记为近似值，避免把估读当作精确数据。
- 依据来源校对公式、变量定义、单位和推导条件。准确解释机制，不用听起来专业但无材料支持的表述补齐内容。

## 5. 设计清晰、统一的科研页面

- 读取可用的 Presentations 演示文稿技能并遵循其当前实现、导出与检查流程。制作文件时使用其支持的工具，不在本技能中固定易过时的 API 或复制整套底层实现说明。
- 将默认技术图示视为需要可编辑的证据。用原生对象制作表格、数据图表、系统框图、流程、时序及有依据的电路示意；明确请求可编辑的技术图示时，遵循演示文稿技能关于原生证据的说明。不要把准确电路、真实波形或研究数据交给图像生成来猜测。
- 优先使用用户的真实电路、芯片、PCB、实验平台或结果图片。使用有依据的技术图示作为主要视觉，不为增加装饰加入无关科技图片。
- 建立一致的字号、页边距、对齐、颜色含义和图注样式。默认封面标题约 40–44 pt、页标题 30–34 pt、正文约 20–24 pt；技术标签以投影可读为准，引用可适当小一些。内容溢出时先精简或拆页，再调整字号。
- 使用简洁的封面与清晰的主画面；按内容选择图为主、图文并列、结果对比或精简表格布局。保持留白，避免每页机械复制同一种结构或堆叠卡片。
- 对结构和背景页使用明确的主题标题；对有充分证据的结果页使用具体、克制的结论标题。删除空泛口号、重复结论和装饰性副标题。
- 放大读者需要检查的电路局部或曲线区域。裁剪时保留理解该局部所需的端口、坐标、单位和条件；必要时在备用页保留完整原图。
- 图表使用稳定的颜色和线型区分对象，用标注解释与主结论相关的部分。保持数据尺度真实，不用视觉处理夸大差异。
- 为关键页添加有帮助的讲解备注、过渡说明和完整引用。避免在幻灯片或备注中加入制作过程、检查记录等面向制作者的内容。

## 6. 完成制作并检查交付

1. 根据用户范围生成完整演示文稿。用户要求 PPT 时持续完成文件制作，除非关键事实缺失需要其回答；不要只返回制作建议或大纲。
2. 检查内容主线、用户贡献、所有数字、证据阶段、公式、单位和文献归属。核对每项主要技术结论是否得到对应材料支持。
3. 检查用户提供的重要图片、标签及内容是否覆盖，核对总页数与语言要求。检查实际可编辑性，尤其是文本、表格、数据图表及重画的技术图示。
4. 渲染并逐页检查实际页面，再检查整体缩略图的节奏和一致性。修复文字溢出、遮挡、错位、低清晰度、难读的曲线或电路标签、被裁掉的坐标和失效的公式显示。自动检查不能替代视觉检查。
5. 按演示文稿技能完成导出与文件验证；按当前环境的文件保存要求保存交付物。用户未要求时不额外交付中间文件或检查报告。
6. 简洁交付演示文稿。仅说明会影响使用的实际限制、待补的关键材料或重要假设，不声称未进行的测试或保存已经成功。
